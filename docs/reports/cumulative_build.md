## The findings

Two predictions fail. Neither is a stop condition, and neither changes a field, a map's order
against the per-class one, or the layouts' order.

1. **Prediction (c) fails on the window's lower end, not on the build.** Every unit of every
   layout of record lies inside prompt 80's bracket (C1), the order is unchanged on both grids
   (O1) and the file's four detect nothing (L1, L2). The product layout's worst case is the
   breach's 5 um latency at the steps: the largest class's channel is that class alone, so no
   counting can move it, and the cumulative worst case equals it exactly (P1). The committed
   window's lower end is that latency rounded up at the fourth decimal, so the one value the
   worst case could not leave lies just below the window as written. The window should have
   been closed at the latency itself; the verdict stays as committed.
2. **Prediction (d) fails on two premature intervals of the free optimum** (A1: door at 0.1 um,
   seal leak at 1 um). No clear time is earlier than the per-class one, anywhere, and the
   clean-out's recovery outputs are all later or equal (R1). In both units the layout's clear
   time moved later by one frame more than the room's did, so the interval in which the layout
   reads clear while the room is not is one frame shorter. The prediction assumed the two clear
   times move together. They need not: the room's is the last cell anywhere still above, the
   layout's the last of its own cells, and summing the larger classes moves each by what those
   classes hold where it is read. A shorter premature interval is the layout reporting clear
   later, closer to the room; it is the safer direction for REQ-A07, and nothing in the
   decision orders the two.

## 1. What was built, against the decision

**The channels.** `config.channel_classes(sizes)` (and `SimConfig.channel_classes()`) names, for
each class k, the classes whose diameter is at or above class k's, largest first. Every reader
sums them with `monitor.channel_sums` (one channel, `channel_sum`): zero, then each named class
added in that order, the order prompt 80's probe added them in, so two readers given the same
fields agree bit for bit. The largest class's channel is that class alone. The channels follow
the diameters, not the class order. There is no switch to the per-class comparison anywhere in
`src/`: the only way to read a class alone is to hand a reader channels that name it alone,
which only tests and the table scripts do, as an oracle.

**The monitor** (`AlertMonitor`). Each class's reading at each sensor is taken as before and
kept (`readings`); the channel readings are summed from them (`channel_readings`), and alerts
open and close per channel on those. `Alert.size_class` and the alert table's `size_class`
column name the channel by the class of its lower size edge, and `reading_on` and `peak` are
the channel's sum. The run file keeps the per-class series in `/transport/sensors/readings` and
adds `/transport/sensors/channels` beside it.

**The arrival maps** (`ArrivalTracker`, and `placement.arrival_from_frames`, the frames'
fallback). Per event, channel and cell, the first step (or frame) time at or after the onset at
which the cumulative count is at or above the channel's limit. `/arrival/` records
`counting = cumulative`; `read_arrival` reads a group without the attribute as `per_class`, and
`placement.arrival_from_run` hands it back with `RunArrival.counting = per_class`, the flag.
`placement.detection_units` refuses runs of the two countings together, naming each side, and
`Units` carries the one counting its units share.

**The all-clear and the clean-out.** `placement.clear_times` (REQ-A07's clear times, through
`clear_units`) reads the channels at the frames. `time_integration.RecoveryTracker` reads them for
the within-spec times (the room's recovery time of ADR-014 C and each channel's) and for the
local recovery field (deviation 1). The 100:1 times compare each class with its own initial
level and stay per class, as the prompt says.

**The records.** ADR-015 C carries a dated amendment (Alex's decision, citing prompt 80);
REQ-A03 says how the channels are formed and its rationale is corrected (Class 5 allows 3,520
per cubic metre at or above 0.5 um and, by the formula, 29.3 at or above 5 um; 3.52 million at
0.5 um is Class 8's limit); `docs/SYSTEM.md` section 4 carries every changed contract (config,
monitor, io_manager, placement, time_integration). The generated regions of SYSTEM.md were
regenerated with the code (`scripts/gen_system_map.py --check` matches at each commit).

**Two guards the prompt did not name** (deviations 2 and 4). A march checkpoint carries the
channels' mark (`monitor.COUNTING_STATE`); a restart from a checkpoint of the per-class code is
refused, since continuing it would put two countings in one map, one alert table and one
recovery time. The loader's check that a clean-out's hold cannot end the run at t = 0 compares
the initial levels' channel sums with the thresholds.

## 11. Deviations and notes

1. **The local recovery field reads the channels.** The prompt lists it, beside the free-area
   mean's 100:1 time, as a ratio-based output that is not a threshold comparison and does not
   change. It is a threshold comparison: ADR-014 C defines it as "the last time the cell's
   concentration is above the class's threshold", and `RecoveryTracker` keeps it from
   `fields[k] >= threshold`. The decision's one rule ("no switch back to the per-class
   comparison") governs, so it reads the channels. Read per class it would be the one
   per-class threshold comparison left in `src/`. The 100:1 times (each sensor's and the
   free-area mean's, and their ratio) compare each class with a hundredth of its own initial
   level and stay per class, and so does `defined` (C0 at least 100 thresholds, where the
   standard's 100:1 time is defined), which belongs to them.
2. **The hold's start check reads the channels.** `config` refuses a clean-out's hold whose
   start is within spec at t = 0 (review 64 S5); within spec is now every channel below, so the
   check sums the initial levels by channel. A start with every class below its own threshold
   and a channel at or above is now accepted, since the room is not within spec under the
   channels.
3. **The alert table's column keeps its name.** `size_class` now names the channel by its
   lower size edge; the column, `Alert.size_class` and the table's other columns are unchanged
   in name and type, and the table records its counting.
4. **A per-class checkpoint refuses the restart** (`time_integration.run`, before the
   configuration's check, and `ArrivalTracker.restore`). The prompt did not ask for it; without
   it a run checkpointed by the per-class code and restarted on this one would hold maps,
   alerts and a recovery time made on two countings. A checkpoint without the maps at all still
   gets step 3's KeyError.
5. **The runner's summary lines** (`scripts/run_scenario.py`) say "channel" for the alerts, the
   latencies and the recovery times; no table script parses those lines.
6. **The rule tests read each class as its own channel** (section 2). A planted two-class
   series of those tests has no size order to sum by, and the rules they pin (the onset, at or
   above, the first time kept, the hold) do not depend on how the channels are formed.
7. **`test_a_restart_across_an_open_alert_writes_the_uninterrupted_table`** looked for a
   checkpoint with an alert open across it and another opening before the kill. On the
   channels the release's alerts all open within one step of each other, so no such checkpoint
   exists; the test now also takes a close after the checkpoint, which changes the table past
   it as an opening did. Both defects it names are still caught (T2: `restart_open_alert_dropped`,
   `restart_table_end_only`).
8. **The sweep's D1 on the channels is tables81's** (E2), not `tables72.py`'s: tables72 compares
   each class with its own threshold in its own code, not through `src/`, so re-running it on
   this branch would change nothing. Its re-score of record stays prompt 79's.
9. **The sweep's clean-out runs are not in E1.** Their initial condition puts every cell at
   100 times every threshold at t = 0, so every channel is above its limit at every sensor by
   construction; prompt 76 also scored no detection on the clean-out.
10. **Prompt 79's and prompt 80's table scripts stopped running whole on this branch.** Their calls
    of `placement.arrival_from_frames` and `clear_times` lacked the channels, which the readers now
    require. `tables80.py`'s `Fine` and `Brackets`, which read through its own probe, ran unchanged
    and gave C1's brackets. Prompt 81b passes both scripts the per-class channels and counting by
    name; what each `--check` then reproduces, and what it cannot, is in "Round 1's fixes (prompt
    81b)".
11. **The plants' first run stopped at the sixth plant.** The worktree's checkout holds CRLF
    line ends and that plant's text holds a newline; `plant81.py` now matches newlines as the
    file's own, and the record is the second, complete run. Every planted file was restored
    byte for byte; the worktree was clean before and after.
12. **The whole suite ran after the code commit**, beside the queue, rather than before it, so
    that the runs could start on a commit; the test files the change touches had passed before
    the commit. U1 is that run.
13. **The standby.** The machine's standby intervals are read from the System event log by
    `standby81.ps1` and taken out of the walls (Q1).
14. **A premature interval counts as shorter only past the subtraction's last bits.** An
    interval is the difference of two frame times; where both clear times moved by the same
    frames the two differences can disagree in the last bits (about 1e-14 s against frames
    about 0.36 s apart). A1 counts an interval shorter only by more than `SUBTRACTION` (1e-9 s)
    in `tables81.py`; without it two further units, each with the same frames under both
    readings, read shorter.
15. **The 320x120 units are taken in `tables80.py`'s scenario order**, not the runner's, so C1
    and A1 line up unit by unit with prompt 80's brackets and clear times; the runner lists the
    clean-out first and the dust before the breach.
