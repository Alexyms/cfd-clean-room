## 1. The design of `grid` and `layout`

The reference advects along the last axis: `mesh_axes` describes each direction with its nodes,
interior faces, left-node indices and a padded SOLID mask, and the y call transposes the field,
the flux, the inflow and the vent mask so that y is last (`solver_transport.py` and
`turbulence.py`, the `.T` calls). The core does not transpose. It keeps every field in the
reference's own row-major layout and walks it along a direction with that direction's stride.

**`layout<D>`** (`core/include/cfdcore/layout.hpp`) is the indexing, and nothing else.

- A cell field is one value per cell, row-major with direction 0 the fastest: [ny, nx] for
  D = 2. The face field normal to direction d is one value per face normal to d in the same
  order, with n_d + 1 entries along d: [ny, nx + 1] for d = 0 and [ny + 1, nx] for d = 1, the
  shapes the transport solver's `flux_u`, `flux_v`, `inflow_u` and `inflow_v` already have.
- `cell_stride(d)` is the offset from a cell to its high neighbour along d (1 and nx for
  D = 2); `face_stride(d)` the offset between adjacent faces normal to d along d, which is the
  same number, since the directions below d have the same extent in both fields.
- `low_face(d, cell)` takes a cell to its low face in the face field normal to d,
  `cell + (cell / (s_d n_d)) s_d`; the high face is one face stride beyond.
- `lines(d)` lists the lines of cells along d, each as its first cell and its low boundary
  face, built once at construction. For d = 1 they run i = 0 to nx - 1, which is the row order
  of the reference's transposed field, so line m of the core is row m of the reference's y call.
- `cell_field()` and `face_field(d)` return zeroed fields of the right length, for allocating
  once at set-up.

**`grid<D>`** (`core/include/cfdcore/grid.hpp`) is the geometry the flux reads, copied once
from the arrays `Mesh` holds: per direction the n_d + 2 nodes (the low boundary face, the cell
centres, the high boundary face, concatenated as `mesh_axes` concatenates them) and the n_d - 1
interior face coordinates; the cell types as given; and a SOLID mask made from them with the
SOLID code handed in (`mesh.SOLID`), so the core keeps no copy of the mesh's codes. `check`
returns the reason an input cannot make a grid (a direction with no cell, faces not one more
than centres, cell types not one per cell), which the binding raises as `TypeError` (ADR-017 B:
a wrong shape is refused at the call). Both are templates on `D`, instantiated at 1 and 2
(`core/src/grid.cpp`, `core/src/layout.cpp`); the binding builds `Grid2` from `x`, `xc`, `y`,
`yc`, `cell_type` and the SOLID code.

**Considered and not built**, because the flux does not read them:

- cell widths, centre distances, face areas and cell volumes (ADR-017 C's list for `grid`): the
  flux takes the volume flux per face, already times the area, as the reference does; the
  divergence update, which divides by the volume, is the transport step's;
- storage owned by `layout` for the resident fields (ADR-017 C: "the staggered field storage"):
  the flux's fields come from Python per call, so the resident storage waits for the run
  object, which owns it for a run;
- the strides of a face field along the directions other than its own, and a general
  neighbour lookup with boundary handling: the flux walks lines, so a cell's neighbour along the
  line and its two faces are all it needs;
- the boundary cell type (`BOUNDARY`) and the obstacle walls' faces: the flux reads SOLID only,
  and the boundary interpretation stays in Python (ADR-017 E);
- `std::mdspan` for the fields (not in GCC 13's library, ADR-017 A) and a binding that takes a
  `Mesh` object (the binding takes arrays, so the core knows nothing of the Python class);
- an instantiation at D = 3 (decision 4: no 3D feature built early). The templates take any
  `D >= 1`; nothing above 2 is compiled.

## 2. `scalar`: the functions and their tests

`core/include/cfdcore/scalar.hpp` and `core/src/scalar.cpp`, namespace `cfdcore::scalar`. Each
port forms its values with the reference's operations in the reference's order, one rounding
each (`-ffp-contract=off`, so a multiply and an add stay two roundings), and nothing is
reassociated.

- **`lagrange_weights` and `scheme<D>`.** `_lagrange_weights`' three expressions, term by term.
  `scheme<D>` computes them once per direction at set-up, for each interior face f, with the
  nodes `quick_face_values` indexes when `advective_flux` calls it (`left = 1..n-1` on the
  nodes with their two boundary faces): positive `(nodes[f], nodes[f+1], nodes[f+2])`, negative
  `(nodes[f+3], nodes[f+2], nodes[f+1])`, at `faces[f]`. On those nodes `quick_face_values`'
  fallback (the far node past the line's end) is never taken, so it is not ported.
- **`quick_face_values`.** The quadratic's value `w0 far + w1 up + w2 down`, added left to right,
  at the interior faces normal to a direction, on the field and its two boundary nodes per line.
  It writes the interior faces only.
- **`limited_face_value(s)`.** `limited_face_values` as written: `d = c_d - c_c`; `c_c` where
  `d == 0`; else `r = (c_c - c_up) / d`, `psi_quick = 2 (quick - c_c) / d`, the least of `2r`,
  `(1 + 3r) / 4`, `psi_quick` and `2` folded from the first, `psi = max(0, that)`, and
  `c_c + (0.5 psi) d`. `np.minimum` and `np.maximum` are copied with NumPy 2.4's rules
  (`np_minimum`, `np_maximum`): a NaN in either gives a NaN, and a tie returns the second
  argument, so `max(0.0, -0.0)` is `-0.0` (measured on every length from 1 to 1,000,
  `results/builder87/zeros.py`; pinned by `test_numpy_min_and_max_return_the_second_of_a_tie`).
  The sign of a zero psi reaches the face value when the upstream value is `-0.0`. A fold from
  the first and a pairwise tree give the same result under that tie rule, so the order of
  `np.minimum.reduce` over its four arrays cannot change a bit.
- **`advective_flux`.** Per line along the direction: the two boundary nodes by the sign of the
  flux at the boundary faces (`> 0` at the low face, `< 0` at the high one, so a zero flux reads
  the cell); at each interior face the upstream value, and without `upwind` the clamp of the
  QUICK value, with a far node in a SOLID cell (the padded mask's False at a boundary node) read
  as the upstream value for both `c_up` and `quick`; then the vents, where the mask is set:
  entering from the SOLID side the inflow value, else the room cell's; and the flux times the
  face value on every face. The reference computes QUICK for both signs and picks one; the core
  computes the one it picks, which is the same value.

**The binding** (`core/python/bindings.cpp`): `Grid2(x, xc, y, yc, cell_type, solid)`,
`ScalarScheme2(grid)` (keeps its grid alive; `weights(d)` returns the six arrays),
`quick_face_values(scheme, d, c, c_low, c_high, positive, out)`,
`limited_face_values(c_up, c_c, c_d, quick, out)` and
`advective_flux(scheme, d, c, flux, inflow, upwind, out, vents=None)`. The fields cross in their
own layout ([ny, nx] cells, [ny, nx + 1] and [ny + 1, nx] faces), read-only, C-contiguous and
aligned; the output is handed in, so a call allocates nothing. A wrong dtype, dimension, layout
or shape, an unaligned array, a read-only `out` or an `out` sharing memory with an input is a
`TypeError`; a direction other than 0 or 1 a `ValueError`. `advective_flux_overhead` takes the
same arguments and makes the same checks without the flux, for the timing.

**The tests.** GoogleTest (`core/tests/test_grid.cpp`, `core/tests/test_scalar.cpp`) checks what
needs no reference: the layout's strides, faces and lines against the multi-index at D = 1 and
D = 2; the grid's nodes, faces and SOLID mask; NumPy's tie and NaN rules; the clamp's hand values
on each branch and its bound between the two cells; the uniform grid's interior weights
(-1/8, 6/8, 3/8 exactly); a uniform field giving the flux times its value exactly on a stretched
grid with SOLID cells and a flux of both signs; a monotone field giving no new extremum; D = 1
against D = 2 on a field constant across y; the boundary, far-solid and vent rules on a line of
eight cells. The parity tests (`tests/test_core_parity.py`, run by CI's core job) call each port
and its reference on the same inputs (section 3).

- **F1, prediction (b) fails in y.** The core is 12.1 times faster than the reference along x
  and 9.7 times along y on the run scored (T6, run 1); the two repeats give 11.8 and 12.0 along
  x, 9.1 and 9.4 along y. The y walk's stride is the likely cause (section 6), so the layout
  prompt 87 set (no transposes, a stride per direction) is what costs it; a y pass that walked
  rows, sweeping every column's face at once, would read the field contiguously with the same
  operations per face, and is the change to try if a later step's timing needs it.
- **F2, the prompt's premise: the product meshes are uniform.** The prompt lists the 80x30,
  160x60 and 320x120 product meshes as "stretched". `configs/clean_room_default.yaml` sets
  `stretch_ratio: 1.0` on both axes, so all three are uniform (cell widths equal to within
  rounding, about 1e-15 m). The tests add a stretched 160x60 so that non-uniform weights are
  tested; the product meshes' weights still differ from 1/8, 6/8, 3/8 in their last bits on most
  interior faces (on 80x30 in x, 53 to 68 of the 77 by weight), from their coordinates'
  rounding, and those match bit for bit too (T3).
- **F3, NumPy's tie rule is part of the contract.** `np.minimum` and `np.maximum` return their
  second argument on a tie, so the clamp can return `-0.0` where an `a < b ? a : b` port gives
  `0.0`. Only `limited_face_values`' planted test reaches it (`tie_first`, T5): through
  `advective_flux` a zero QUICK value is too rare among the planted fields for the tie between
  zeros of two signs to arise. The rule is pinned by its own test, so a NumPy build that
  changed it would be named.

## Deviations and limits

- The binding takes the output array (`out`) instead of returning a new one, so the core
  allocates nothing per call; the reference returns a new array.
- `advective_flux_overhead` is a module function that exists for the timing only.
- `quick_face_values`' far-node fallback is not ported: on the nodes the flux hands it the far
  node always exists (section 2). Its other caller, the momentum predictor, is step 4's.
- The captures are not committed (`results/builder87/captures/`, 120 calls, about 65 MB).
- The weights were read back through the binding and compared in pytest; the GoogleTest test
  checks the uniform grid's exact eighths.
- The parity tests take about 5 s on WSL2 (350 cases). CI's core job runs them with the rest of
  `tests/test_core_parity.py`; nothing in `.github/` changed.
- The whole suite at the probe's commit with this report's tests (4a5b872): on Windows 3,101
  passed and 1 skipped (`tests/test_core_parity.py`, which needs the core); under WSL2 with the
  core built, 3,451 passed (`results/builder87/suite_windows.xml`, `suite_linux.xml`).
